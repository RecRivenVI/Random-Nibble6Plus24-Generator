# 里程碑 1：完成 B 模式、人工体验与性能评估

状态：进行中，已按使用者决定收敛范围。当前只登记本里程碑；完成条件由使用者验收，不自动安排后续里程碑。

## 范围

本里程碑只完成 Minecraft 26.3 的 B：仅执行目标区块 FEATURES，放弃邻区装饰贡献，严格拒绝所有越界生成副作用。使用已验证的紧凑结构输入、缓存生物群系采样与按需局部地形查询；不能证明等价的读取明确采用精确回退，不使用假空气、近似高度或 physical master-seed 数据。

交付包括 B 的完整数据与生命周期验收、一张可以人工进入并持续探索的新实验地图，以及足以判断是否需要优化的端到端性能测量。不是只交付离线快照，也不是只让单个生成函数跑通。

A/C 的源码、对照入口、研究结果和未通过证据全部保留；本轮不继续扩展它们，其支持范围、动态冲突替换及物理接收不再是首个里程碑的完成门槛。三方案的技术边界仍见[FEATURES 方案边界](../design/architecture-features.md)。

Seed V1、WorldOptions.seed() 权威、旧世界的 Feature Ordering V1/2、Mosaic format V2、Structure Overlay、SPAWN 与物理运行期语义保持。只为新实验地图显式接入已验证的 B，不迁移或覆盖旧存档、不更改生产默认分流。不得以已有 Ordering 2 展示路径代替按需 B，却宣称新的 B 已完成。

本里程碑增加性能评估，不自动授权优化。使用者已单独授权第一项性能修复：以反向依赖和分状态引用计数替换物理计划完成时的全表扫描，保持状态要求、调度语义和生成合同；随后授权第二项：单个 B 目标生成内复用同种子的原版结构来源求值，目标装饰使用的可变结构移交并与后续只读查询隔离。两个修复都须通过原路径对照。不开启模板锁优化、A/C、D2、V3、C2ME、WorldPreset、Preview 或其它产品功能；不改线程数或调度语义来制造测量结果。

## 完成条件

- B 每个目标只执行一次完整原版 FEATURES；没有外围 FEATURES writer。外部生成读取使用同一 S(C) 的已定义装饰前输入，所有精确回退明确计数。
- 越界方块、直接 Chunk/section 写入、BE 与 pending NBT、实体、block/fluid ticks 和后处理都在副作用发生前拒绝；目标内的完整数据及原版随机调用顺序保持已验证的 B 语义。
- 与保留的原 B、同版本独立原版装饰前 Oracle 比较完整输入和目标数据；覆盖三维度、结构、洞穴、表面、树木、实体、BE、ticks、后处理及已知精确回退案例。不把 B 声称为完整九 writer Vanilla FEATURES parity。
- 顺序、并发、宿主 seed 和物理邻区独立性、异常传播与 session 清理通过。原生随机字段只沿用使用者批准的有限验收例外，保留原始数据与严格 hash。
- 新实验世界的新 Chunk 确实使用按需 B，随后复用真实 Artifact、物化、POI、LIGHT、SPAWN、FULL 与正常 physical simulation；运行计数能区分该路径与旧 Ordering 2 实现。实体、BE、ticks 不重复激活。
- 新地图可进入、探索未生成区域、正常保存退出并重进；重载 FULL Chunk 不重新生成 Artifact，修改保留，普通 Vanilla 与旧 Mosaic 存档不退化。已有身份热路径、SPAWN 快路径、POI 主线程归属及关闭取消修复保持。
- 完成性能测量，分别报告模块成本与真实请求到可见/可玩区块的成本；没有可靠观测的指标明确未测，不以平均模块耗时推算玩家体验。
- 使用者人工体验并确认地形硬边界、装饰切断、光照、跨区块交互、持续探索和保存重进。自动检查、运行检查与人工验收分别记录。
- 给出是否需要优化的判断、主导瓶颈和建议优先级；不在未经授权时直接实施优化。

## 性能测量

受控测试沿用四逻辑 CPU、低优先级、单个重负载 JVM；A/B 对照使用相同资源限制、JVM、种子、目标区域、视距/模拟距离和固定探索轨迹，不长时间吃满整机 CPU。后续客户端人工采样按使用者明确授权使用正常优先级、不限制 CPU、16GB 堆上限；报告实际运行参数，不能把它与受限结果直接比较。

先比较原 B 与按需 B 的相同代表目标，分开记录结构/地形准备、FEATURES、快照/Artifact、局部列与噪声批次、完整邻区回退、内存和分配；包含冷启动与重复样本，不依赖固定先后顺序给出收益结论。

再使用新实验世界测量首次出生、已生成区域重进与持续新区探索。以 8/8 为主要固定负载，并记录 12/12、16/16 的可承受程度；明显落后时允许提前结束并保留实际数据。普通 Vanilla 使用相同限制和同类负载对照，不将其原版内容与 B 内容差异当作 correctness 失败。

每项负载至少记录：

- 请求数量、去重、队列深度、实际并发和取消数量。
- 请求到 canonical 开始/完成、Artifact、物化、POI、LIGHT、SPAWN、FULL、ticking 与 send-ready 的时间；可靠可观测时记录 packet enqueue，不把它当作已经渲染。
- canonical/FULL/send-ready 吞吐，延迟分布和最慢典型区块的关键路径，首次玩家就绪和保存退出耗时。
- 当前视野就绪率、CPU、服务端主线程卡顿、GC、堆占用；按需使用 JFR 分析计算、锁等待、I/O 和重复工作。
- 资源限制及玩家人工反馈；区分继续飞行、停下补齐与返回已生成区域的体验。

性能通过标准不是预设一个漂亮的 chunks/s，而是证据能回答：B 是否达到使用者可接受的探索体验、主要等待发生在哪里、是否值得优化，以及预计该先处理哪个问题。若明显不足，如实报告，不能仅靠构建和模块 benchmark 宣称里程碑完成。输出放在对应验证的固定 ignored result 路径，不提交 profiler、世界或本机数据。

B 的独立严格基线和按需读取对照已有证据，已有完整目标数据及有限原生实体验收；实际范围见[生成实现状态](status-generation.md)。

按需 B 已接入明确标记的新实验世界，复用既有 Artifact、物化与完整生命周期；两个独立宿主各 19 项 detached 交接对照、三维度 FULL、32 次同目标并发去重与修改后重载已通过。新 B 使用独立隐藏生成器身份，不转换旧 Ordering 1/2 世界。
