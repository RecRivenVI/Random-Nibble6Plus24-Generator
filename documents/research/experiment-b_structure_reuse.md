# B 会话内结构来源复用

调查日期：2026-10-15。结论：在不改变 B 读取与严格切断规则的前提下，单目标同种子的结构来源复用显著减少重复求值；仍没有解决全部局部地形计算和探索前沿等待。

## 问题

同一 B 目标的邻区列查询和完整地形回退会反复求值重叠的结构来源。能否复用原版结果，而不共享装饰正在修改的结构、跨种子污染或改变模板锁？

## 方法

复用范围只属于一次 B 准备，同一宿主实例、local seed 和生成设置。原版引用半径八与 B 读取半径一组成最多 361 个来源的有限仓库；保存原版 `createStructures` 结果，包括空结果，不保存邻区完整地形或旧 session。各查询仍独立调用原版 `createReferences` 与 `Beardifier`。

目标拥有或引用的来源在装饰前移交出去。其 pieces 可以被原版放置修改；后续邻区读取需要相同来源时重新原版求值一次，保留为只读输入。仓库结束或异常时清空，不成为存档权威。原 B、无复用按需 B、A/C 与旧存档入口保留；模板锁和调度不改。

读取与完整交接使用两个无关宿主，独立原版结构对照覆盖七类结构、邻区 start 与地形适配。方法与固定结果分别见 [B 验证](../../validations/conformance-feature_b/validation.md)和[装饰前验证](../../validations/conformance-prefeatures/validation.md)。有限原生实体例外保持，原始数据与严格 hash 不改。

性能两组分别 fresh JVM/world，四逻辑 CPU、亲和性 `0xF00`、BelowNormal、单个高负载 JVM、8/8 与 60 秒固定 PLAYER ticket 前沿，全部结构开启。无复用组通过仅 probe 可调用的原 B 准备入口运行，保留已完成的物理计划增量修复。结果在性能验证的 `b-source-reference-v8-s8` 与 `b-v8-s8` 固定目录，不使用日常地图；CLI 不是实际玩家进入或渲染。

## 发现

普通主世界实际查询中，来源求值从 2,601 次降到 362 次；额外一次是装饰可变对象移交后的安全重新求值。两个精确回退目标的逻辑请求为 4,913 与 4,335 次，仍只求值 362 次。关闭后 resident 为零；没有把完整地形回退改成默认值。

首轮受控结果如下；每组一次，不能宣称排除全部运行噪声。

| 指标 | 无复用按需 B | 会话内复用 B |
| --- | --- | --- |
| canonical 区块/秒 | 3.97 | 7.14 |
| 60 秒 FULL 完成 | 73 | 202 |
| 60 秒 send-ready 完成 | 34 | 144 |
| 第 55 秒当前视野就绪 | 9.7% | 42.6% |
| 初始中心 ENTITY_TICKING 就绪代理 | 46.62 秒 | 27.96 秒 |
| 目标准备平均时长 | 1.11 秒 | 0.71 秒 |
| Structure CPU 采样占比 | 39.46% | 11.26% |
| 已采样模板锁累计等待 | 46.17 秒 | 11.93 秒 |
| GC 暂停累计 | 1.83 秒 | 2.58 秒 |
| 采样堆峰值 | 1,565 MiB | 1,370 MiB |

锁等待是跨线程累计，且受 JFR 事件阈值影响，不能写成单个玩家等待。更多区块完成后 GC 累计上升，不代表单目标 GC 变差。两组没有测到服务端 lag 警告，不声称已测最大 lag 为零。

复用组 CPU 栈中，局部列查询约占 44.3%，噪声批次构造约占 32.4%；它们是包含调用栈的重叠指标，不能相加。剩余主要计算落在噪声、生物群系搜索和局部地形查询；模板锁仍存在，但本轮不处理。send-ready 仍受整个物理依赖前沿就绪约束，不等于画面已出现。

## 结论

这一项复用有效，约获得 80% 的首轮生成吞吐提升，但不能据此宣称首个里程碑或正常高视距探索已经通过。人工体验另行记录，不能由 CLI 吞吐替代。

不继续模板锁、Noise 或其它优化。原版结构生成算法、Seed V1、B 边界、旧 Ordering 1/2、format V2 与物理运行期语义保持；工作区成果未暂存、未提交、未推送。
