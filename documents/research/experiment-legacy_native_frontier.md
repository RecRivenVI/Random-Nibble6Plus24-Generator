# 1.21.1 冷票据前沿四组性能筛选

调查日期：2026-10-16。四组单实例冷负载已完成，但默认 B、有限环 B 与缩锁 B 均未在 60 秒内完成 Artifact/FULL。候选的热点变化是真实的，尚不能据此保留端到端优化或宣称本 Target 可玩。

## 问题

H121-R 有限环与 H121-T 缩锁是否能单独改善正常物理前沿？必须区分“完成更多结构准备”与“实际区块发送就绪”，不能用模块耗时或线程累计等待替代端到端结果。

## 方法

输入指纹 0C6D8DDF4C89215BEA0F86FBA850732580F31DAF83D90440587DDED3FA209A42；产品算法与 0D35 完整结构 B 通过时相同，只增加独立 probe。使用一个游戏 JVM、四逻辑 CPU、亲和性 3840、BelowNormal、3 GB 堆、8/8、60 秒，依次运行普通 Vanilla、默认保守 B、有限环 B、有限环加缩锁 B。每组 fresh JVM/save，master 123456789、初始 (125,-37)，15/30 秒各沿 X 移动两 Chunk。

使用本版原生 DistanceManager 玩家票据与 ChunkTrackingView，离线 token 不登录或注册实体。schema 2 要求 token 构造后所有维度仍冷，恰好一次探针专用出生查询隔离；初版污染和修正见[票据 token 故障](incident-legacy_ticket_source_spawn.md)。窗口后的关闭取消不计入性能，四组均正常退出且没有新增崩溃报告。

### 目标关键路径

焦点 local seed 为 -5161763991829980711。有限环加缩锁 B：初次视野需求约 0.013 s，物理 FULL 计划约 0.232 s，准备入队约 0.537 s，worker 开始约 1.636 s，B 入口约 1.683 s；到 60.027 s 截止仍未完成 canonical/Artifact。入队等待约 1.10 s，活动 worker 跨度至少 58.39 s；没有 materialization、POI、LIGHT 或 FULL 完成可计时，不能给它们填零成本。

有限环但未缩锁的焦点则入队约 0.562 s，到窗口结束仍未开始 worker。默认 B 焦点等待约 8.87 s 后进入 worker，仍未完成。它们说明队列顺序与资源竞争会放大等待，但当前缩锁焦点本身仍长期未完成，不是只改优先级就能解决。

### 剩余成本与证据边界

缩锁 B 的排他 CPU 样本约 59.3% 为其它结构、36.8% 为 Noise/Surface/Biomes，主线程和 GC 不是本窗口第一主因。当前每个完整 B 仍构造九份真实 CARVERS，各自又准备九份 stored palette；模块已证明 owner 加 80 borrowed context，通常解析 81 次结构输入，每次 289 个 source，即 23409 个 set-position/source 求值入口，外围原生阶段另计。它们不是 23409 个完整地形 Chunk。

本轮观察到 486387 个已完成 source 检查，但未完成任何 Target，因此不能将它除以完成 Target 数或声称每目标已减少多少。命中后的 Jigsaw/高度/密度工作仍原样执行；下一项应先核验同 S(C)、同配置、同 source 的重复结果能否在一个 B 准备生命周期内安全复用，尤其是可变 pieces 的独占移交，不应直接重写原版 Jigsaw。

## 结论

首轮不足以让 H121-R/H121-T 单独达到主要端到端保留门槛，均继续默认关闭，不开展没有辨别力的三组重复筛选。已有独立结构/地形与 B 输出证明仍有效，但不提升为主世界运行期或性能通过。

下一项有界假设 H121-U 是本目标生命周期内的精确 source 复用，不是全局缓存或 placement 裁剪：先从本版依赖推导范围与 mutable pieces 移交，未知配置精确回退；最多两轮，并严格对照独立原生/既有 B，再用相同冷前沿衡量。若不能证明等价或端到端仍无收益，不通过放宽合同或持续新增近似来继续。
