# 原生读取与生成交接候选筛选

调查日期：2026-10-20。把原生 B 准备从 EMPTY 读取回调移到首个 STRUCTURE_STARTS 生成步骤，首组受限筛选没有收益，平均等待退化约 6.59%；候选已撤回，没有改变调度器或推广到 NeoForge。

## 问题

既有 Fabric 样本中，中心目标在 0.317 秒请求、12.418 秒才开始准备，排到第七十四个 canonical 开始位置，16.742 秒发送就绪。文件完成回调向全局后台执行器提交准备，是否导致原生生成优先级不能及时影响可见区块？

## 方法

只对原生 B capability 通过的世界推迟准备；EMPTY 保留真实加载输入，首个必要结构步骤完成同一 canonical 准备。不改变线程数、票据、随机流、内容、已有世界或未知模组回退。对照由仅探针开关调用同一构建内的原读取入口，候选不依赖该开关。

候选先通过三维度原生运行／保存／重载，另以不安装 MCP 的实际客户端验证首次进入、真实 LevelChunk、二十玩家 tick 和正常退出。隐藏测试存档的原生实验性数据确认，由专用 probe 调用原生继续加载回调；不模拟 GUI 输入，不改世界身份或生产判断。最初缺声明模块、未批准实验性测试存档的测试入口失败原样保留，不当作 worldgen 内容失败。

性能为单实例、四逻辑 CPU、低优先级、8/8、六十秒固定移动。同一源码、两个 fresh 世界和 JVM；没有同时运行本线程其它高负载测试。

## 发现

| 指标 | 原读取入口 | 生成步骤候选 |
| --- | --- | --- |
| FULL | 375 | 377 |

| 全部需求受限平均等待 | 36.535 秒 | 38.943 秒 |

实际准备时序已改变：原入口有 112 项准备先于 EMPTY 完成、358 项之后；候选为 0 与 472，不是开关未生效。候选整机竞争较低，仍没有看到吞吐改善，早期可见区块更晚。一次筛选足以否定保留，不以三次重复寻找有利结果。

证据为 `validations/performance-worldgen/result/b_milestone/26.3-fabric/native_generation_handoff_first/physical-biomes-screen.json`。三维度生命周期标签为 `native_generation_handoff`；实际原生客户端为 `validations/integration-production_lifecycle/result/native-client-handoff/goal_native_handoff_approved`。这些是已撤回候选的范围证据，不冒充最终交付运行。

## 结论

没有证据表明这处最小交接能改善主要吞吐；已撤回产品接入及运行开关，保留只读分析与研究记录。当前继续使用原读取交接、已通过的部分 BIOMES／TERRAIN 和私有副本组合。排队时间仍需在最终 Vanilla 配对中报告，不能把本次否定结果解释为所有实现开销都已不可避免。
