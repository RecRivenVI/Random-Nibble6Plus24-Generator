# 1.21.1 结构缓存缺少原生气候搜索状态

调查日期：2026-10-17。H121-U 首版虽然通过代表世界对照，但原生组件证明其键和续流状态不完整；本文不把组件反例伪称为已定位的默认世界方块差异。

## 问题

仅以同 world/configuration/seed/source 复用原生 StructureStart，是否能保持后续 stored-biome 与地形查询的原生条件？

## 方法

审计本版 `Climate.RTree.search` 与 `SubTree.search` 字节码。用同版原生类构造温度为 -1/+1、其余参数相同的两条气候记录 A/B，查询温度零的等距点。保持官方原生搜索方法不变，分别控制上一次命中，双向比较查询返回值和下一次查询。临时实验在仓库外，原始输出由任务写入 `build/research/climate-source-u/native-component.json`；长期回归进入 Target 单元测试。

## 发现

原生 RTree 将线程内 `lastResult` 作为搜索初值，只有距离严格改善才替换。先命中 A 再查等距点得到 A，先命中 B 则得到 B。这是实际原生组件的合法行为，不是浮点容差或错误 RNG。

即使某次结构计算的返回数据不变，也不能省略它对下一次查询的影响：入口 A、原生主体查询 B、再查等距点得到 B；直接返回缓存、不执行主体时，下一次等距点得到 A。重放该次原生出口 leaf 后，下一次查询恢复为 B；反方向也需同样验证。因此不能把缓存状态只当作性能细节，更不能固定生产排序或新增 canonical ignore。

首版指纹 `11428EA0D88DD25ABC2440A63F036EC1B30E2BFB9D7D0A8725A28D44D4132E1E` 的十八项装饰前结构对照与四项完整 B 冒烟均通过，首个 B 宿主实际将 23,409 次查询降为 442 次原生求值。但这些正例不能证明遗漏状态是安全的。随后十八项完整 B 结构队列主动停止；控制器停止时有十八份 summary，已启动子 JVM 未强杀、正常完成后共十九份。保留原始证据，不计整套 PASS，也不将主动停止计为内容 FAIL。停止记录为 `build/research/climate-source-u/abandonment.json`，没有运行首版性能筛选。

第二版限定：只支持已审计的原生 biome source；MultiNoise 的同一个原生 RTree、同线程入口 leaf 身份也必须匹配才可命中，命中时重放实际原生出口 leaf，入口不同则执行原生计算并替换该坐标的一条缓存。Fixed/End 没有这个 RTree 状态，不伪造一个。仍保留目标图独占移交、441 坐标上限、关闭清理、未知环境精确回退；不重置整个原生缓存、不改变树的遍历或 ties 规则。

## 结论

首版不满足完整输入条件，不保留为生产默认；代表 Oracle 通过不能替代可变输入审计。第二版属于本假设的第二次实现，仍默认关闭，须重新执行独立 Oracle 和性能门禁。组件证明只允许修复缓存键与续流，不授权放宽 B、保存格式或原生随机性规则。
