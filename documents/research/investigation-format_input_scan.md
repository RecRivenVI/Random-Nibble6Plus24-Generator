# 根格式任务的本地输入遍历

调查日期：2026-10-17。项目级 FileTree 提前排除可以避免根格式任务枚举庞大的本地运行数据，同时保持模板定义的文本检查集合；模板插件、证据与格式门禁不修改。

## 问题

完整检查长时间停留在根 `spotlessMisc` 的输入准备，而非游戏生成或格式工具执行。默认 Git 属性换行判断和后续源集合快照都会遍历本地文件树，晚应用的排除条件不能避免目录枚举。

## 方法

只读线程栈分别定位到 `GitAttributesLineEndings`、`DirectoryWalker` 和文件集合快照的 `FileTreeWalker`。两次长时间输入扫描在核实属于本仓库的 daemon 与父进程后主动中断，没有关闭游戏；它们均不计构建 PASS，也不是 JVM fatal/OOM。

根 build.gradle.kts 通过公开 Spotless 配置使用 LF，并在输入 FileTree 中提前排除实例、结果和原本不属于根格式任务的目录。模板本体不修改。Windows 脚本仍由组件的 CRLF 格式器负责。

## 发现

工具布局回归直接对照当前模板 RootFormatting 的全部根输入字面量、验证文本扩展集合和必要排除项，验证额外提前排除目录不覆盖任何本应检查的路径。七项布局测试、五项客户端偏好测试、六项 BOP 判据测试、二十七项性能汇总测试及五十七份 PowerShell 语法检查通过，1.21.1 probe 编译通过。

新增配置不跳过 spotless、check 或发行检查，不为加速清理世界、结果或缓存，也不把受保护模板文件复制成项目内新实现。完整根检查的最终结论仍需以单独执行结果登记，不用上述组件通过代替。

## 结论

保留项目级输入配置与范围一致性回归。此项只修复开发验证的文件扫描，不属于生产生成优化，不改变任何 Chunk 内容或调度。
